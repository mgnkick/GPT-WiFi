# WiFi Expert — Android

WiFi Expert — инструмент диагностики Wi-Fi и локальной сети для смартфонов Android. Проект сохраняет React-интерфейс исходного приложения, но системные операции выполняются нативным Android-плагином, а не имитациями на клиенте.

## Функции

- Сканирование реальных точек доступа, полученных от `WifiManager`: SSID/BSSID, уровень сигнала, частота/канал, диапазон, ширина канала (если Android её предоставляет), стандарт Wi-Fi и данные безопасности из `ScanResult`.
- Чтение текущих Wi-Fi/DHCP-параметров Android: адрес телефона, шлюз, маска подсети и наличие VPN-транспорта.
- Поиск реальных доступных узлов в локальной подсети с проверкой распространённых TCP-портов и ICMP-reachability, когда ОС/устройство это допускает; определение открытых портов, задержки и MAC из ARP-таблицы, если Android отдаёт эти сведения.
- ICMP ping и отчёт диагностики на основе фактических ответов.
- Тест скорости загрузки/отдачи по реальному трафику к Cloudflare speed test, плюс базовый ping/jitter/bufferbloat.
- Анализ каналов и рекомендации на основе реально обнаруженных точек, база знаний, переход к интерфейсу роутера и ссылки на внешние сервисы.

## Что важно знать

Android ограничивает частоту Wi-Fi-сканирований и доступ к некоторым системным полям. Для сканирования точек доступа потребуется разрешить приложению доступ к ближайшим Wi-Fi-устройствам/геоданным и, в зависимости от версии Android, включить системную геолокацию. Если ОС скрывает SSID/BSSID, стандарт, ширину канала или MAC-адрес, приложение показывает отсутствие данных, а не придумывает значения.

Сканирование LAN — активная проверка подсети, а не гарантированная инвентаризация: устройства, блокирующие probes или TCP-порты, могут не обнаружиться; Android также может не предоставить ARP MAC. Показанные названия/категории устройств ограничены тем, что реально получилось определить по открытым портам. Тест скорости требует подключения к интернету и доступа к `speed.cloudflare.com`; доступность внешнего IP/ISP зависит от публичного сервиса геолокации IP. Эти сетевые запросы выполняются с устройства и могут передавать этим внешним сервисам IP-адрес пользователя.

Встроенные системные диагностики доступны в **установленном Android APK**. При открытии проекта через обычный браузер нативный Wi-Fi-плагин и ICMP ping намеренно не имитируются и сообщают, что нужны Android.

## Автоматическая сборка APK через GitHub

1. Создайте пустой репозиторий GitHub и загрузите в него все файлы этого проекта, включая скрытую папку `.github`.
2. Откройте вкладку **Actions** и включите GitHub Actions, если репозиторий попросит этого.
3. После `push` в ветку `main` или `master` автоматически запустится **Build Android APK**. Также можно запустить его вручную через **Actions → Build Android APK → Run workflow**.
4. Когда workflow завершится успешно, откройте его запуск и скачайте `WiFiExpert-Android-APK` в секции **Artifacts**. Это устанавливаемый debug APK: перед установкой на смартфоне может потребоваться разрешить установку приложений из выбранного источника.
5. Чтобы прикрепить APK к GitHub Release, создайте и отправьте тег версии, например `v1.0.0`; workflow соберёт APK и приложит его к релизу.

Рабочий процесс создаёт Android-проект Capacitor в CI, устанавливает Android SDK и собирает `android/app/build/outputs/apk/debug/app-debug.apk`. Сгенерированная папка `android/`, `node_modules/` и `dist/` не включены в исходный репозиторий — это намеренно, так как CI получает их в процессе сборки.

## Локальный запуск веб-интерфейса

Требуется Node.js 22 или новее:

```bash
npm install
npm run dev
```

В браузере остаются доступными информационные разделы интерфейса; для нативных операций используйте Android APK.

## Лицензия

Исходные файлы содержат указание SPDX `Apache-2.0`; перед публичным распространением проверьте лицензии всех зависимостей и элементов брендинга исходного проекта.
